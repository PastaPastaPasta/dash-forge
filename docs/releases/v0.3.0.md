# Dash Forge v0.3.0

Released 2026-11-24.

**Forge is on Dash mainnet.** Its four contracts are registered on mainnet, and [forge.dashhq.org](https://forge.dashhq.org) now serves mainnet. Testnet stays live, and its web app moved to [testnet-forge.dashhq.org](https://testnet-forge.dashhq.org). `dg` and `git-remote-dash` still default to testnet in this release.

**Mainnet DASH is real money, and there is no faucet.** Every write costs real credits. Get them from the [Dash bridge](https://bridge.thepasta.org/?network=mainnet) or the web app's identity flow (**Sign in → Create a new identity** on forge.dashhq.org).

## Networks

| Network | Supported in v0.3.0 |
|---|---|
| **Mainnet** (protocol 14) | **Yes.** Forge's four contracts are registered in contract group `<MAINNET_GROUP_ID>`. The hosted web app at [forge.dashhq.org](https://forge.dashhq.org) and this release's IPFS build read mainnet. Wallet sign-in uses DashPay App Connect v2 and its system contract (`H8F9mP1BM55TE1ShsxPZHzhyinaMdY9bMmP85mkDhcJJ`), so there is no key-exchange contract on mainnet. |
| **Testnet** (protocol 14, chain id `dash-testnet-51`) | **Yes**, and still the default network of `dg`, `git-remote-dash` and the Actions. Contract group `EXgzBMpwC7RMjSU4WQghLAnfboswsssMGiXRtiV1hmBC`. Its web app is [testnet-forge.dashhq.org](https://testnet-forge.dashhq.org). Test DASH comes from the [Dash testnet faucet](https://faucet.testnet.networks.dash.org) or [faucet.thepasta.org](https://faucet.thepasta.org). |

**Choosing mainnet in the tools.** Any of these selects it:

- `--network mainnet` on a command;
- `dg auth new --network mainnet` or `dg auth login --network mainnet`, which records mainnet as your default network;
- `DASH_FORGE_NETWORK=mainnet` in the environment;
- git config `dash.network mainnet` (globally, or in one clone).

A clone made by `dg clone` or `dg init` records its network, so its `git push` and `git fetch` stay on it whatever your default is. In the Mirror Action, the check action and the GitLab template, set `network: mainnet` (`FORGE_NETWORK: mainnet`).

## Highlights

New since v0.2.0:

- **Mainnet**, as above.
- **Sign in from the terminal with your DashPay wallet.** A bare `dg auth login` (or `--wallet`) shows a QR code; the wallet grants a limited key.
- **Where your key came from** is shown in `dg auth status` and the web app's Settings.
- **The web app** shows what a Platform write is doing, walks an empty repository's owner through the first push, and on testnet renews browser keys in the wallet first.
- **`dg pr diff`** works outside a clone and shows a merged pull request's changes.

The full list is in the [changelog](../../CHANGELOG.md#030---2026-11-24). Install, verification and the IPFS build work as in [v0.2.0](v0.2.0.md#install), with `0.3.0` in place of `0.2.0`.

## Upgrading

**From v0.2.0.** Install this release over the old binaries. Earlier builds know no mainnet deployment and stop there with [E702](../errors.md#e702), so update before you use mainnet. Your testnet identity, keys and clones are unchanged.

**Starting on mainnet.** Mainnet is a separate network: a testnet identity, its repositories and its keys do not exist there. Create a mainnet identity (`dg auth new --network mainnet`, or in the web app), fund it, and push each repository you want there from its clone with `dg init --network mainnet`.

**Bookmarks.** forge.dashhq.org now shows mainnet; testnet repositories are at testnet-forge.dashhq.org. A passkey you made at forge.dashhq.org for a testnet identity does not work at testnet-forge.dashhq.org (a separate site, on purpose), so sign in there with your identity file, recovery phrase or wallet.

**Workflows.** Pin `@v0.3.0`. A workflow for a mainnet repository sets `network: mainnet`, and its `DASH_FORGE_KEY` must be a key for your mainnet identity.
