# Dash Forge v0.3.1

Released 2026-11-26.

**`dg` and `git-remote-dash` work on testnet again.** Testnet moved to Dash Platform protocol 15 at 2026-11-25 19:41:30Z (epoch 20634, block 740732), before v0.3.0 was published. Much of v0.3.0 fails on a protocol 15 network. Anything that resolves a DPNS name stops with

```
Proof verification error: … unable to deserialize proof data contract within its bounded budget:
UnexpectedVariant { type_name: "DataContractInSerializationFormat", allowed: Range { min: 0, max: 1 }, found: 2 }
```

clones and fetches stop with a proof error, and writes are refused. Reads by identity id still work. v0.3.1 fixes that. It is built on the Platform SDK 5.1.0, which speaks protocols 14 and 15 and learns which one a network runs from the network's first proof-verified answer.

**Mainnet is unaffected.** Mainnet still runs protocol 14, and v0.3.0 keeps working there. What v0.3.1 writes on mainnet is the same as what v0.3.0 writes: the SDK picks the format from the network's protocol version, and protocol 14's formats and document ids are unchanged in 5.1.0. Upgrade anyway: v0.3.0 fails on a protocol 15 network, so it would fail on mainnet the same way once mainnet moves to protocol 15.

## What changed

- **Platform SDK 5.0.0-rc.8 → 5.1.0**, in `dg`, `git-remote-dash` and the web app ([#756](https://github.com/PastaPastaPasta/dash-forge/pull/756), [#758](https://github.com/PastaPastaPasta/dash-forge/pull/758)). To see which protocol a network runs, use `dg doctor`: it prints the version it proved, 15 on testnet and 14 on mainnet.
- **Document history** (an issue's, pull request's or comment's earlier revisions, read when posts are made public or opened at an older revision) pages by revision: on protocol 15 each page continues after the last revision read, and on protocol 14 it starts at the last revision's time and skips revisions already read.
- **Organizations (testnet only)** sign with a pure-Rust BLS library (`blstrs_plus` 0.10) in place of blst's assembly, because the new SDK needs a newer blst than the old library allowed. The signatures are the same: the organization signing test vectors pass unchanged.
- **A document write the 5.1 SDK reports as "state transition outcome is unconfirmed"** (a send that may have reached a node without proof of the result) is settled instead of failed: `dg` and `git-remote-dash` wait for the result, check whether the write landed and send the same bytes again, and the web app checks whether the document landed. Neither signs a second copy ([#759](https://github.com/PastaPastaPasta/dash-forge/pull/759)).

Nothing else changed in the tools. Everything in [v0.3.0](v0.3.0.md) still applies, except that testnet now runs protocol 15, not 14.

## Upgrading from v0.3.0

Install v0.3.1 over v0.3.0 the usual way (below). Nothing needs migrating: v0.3.1 reads v0.3.0's config file, stored keys and key backups as they are, and does not rewrite them.

**Workflows.** Pin the Mirror Action and the check action to `@v0.3.1`. A workflow pinned to `@v0.3.0` installs the v0.3.0 binaries, which fail on testnet as described above.

## Known limitations

- **Document history on testnet**: until the SDK has learned that testnet runs protocol 15, 10 or more revisions that share one timestamp can end a history read early. This cannot happen on mainnet (protocol 14).
- **Settings that follow your identity and organizations are still testnet only**, as in v0.3.0.
- The limitations listed for [v0.3.0](v0.3.0.md#known-limitations) still apply.

## Install and verify

Install, verification and the IPFS build work as in [v0.2.0](v0.2.0.md#install), with `0.3.1` in place of `0.2.0`. Release binaries are built for Linux (x86_64 and arm64, plus a static x86_64 musl build), macOS (Intel and Apple silicon) and Windows (x86_64). `SHA256SUMS` lists every file, and each file has a GitHub build-provenance attestation.

What changed is in [CHANGELOG.md](../../CHANGELOG.md). How version numbers work is in [VERSIONING.md](../VERSIONING.md).
