# Dash Forge v0.3.1

Released 2026-11-26.

**Testnet works again.** Testnet moved to Dash Platform protocol 15 at 2026-11-25 19:41:30Z (epoch 20634, block 740732). v0.3.0's `dg` and `git-remote-dash` cannot use a protocol 15 network: their reads stop with an error such as

```
Proof verification error: … unable to deserialize proof data contract within its bounded budget:
UnexpectedVariant { type_name: "DataContractInSerializationFormat", allowed: Range { min: 0, max: 1 }, found: 2 }
```

and their writes are refused. v0.3.1 fixes that. It is built on the Platform SDK 5.1.0-rc.2, which speaks protocols 14 and 15 and learns which one a network runs from the network's first proof-verified answer.

**Mainnet is unaffected.** Mainnet still runs protocol 14, and v0.3.0 keeps working there. What v0.3.1 writes on mainnet is the same as what v0.3.0 writes: the SDK picks the format from the network's protocol version, and protocol 14's formats and document ids are unchanged in 5.1.0-rc.2. Upgrade anyway: v0.3.0 cannot use a protocol 15 network, so it would stop on mainnet once mainnet moves to protocol 15.

## What changed

- **Platform SDK 5.0.0-rc.8 → 5.1.0-rc.2**, in `dg`, `git-remote-dash` and the web app ([#756](https://github.com/PastaPastaPasta/dash-forge/pull/756)). `dg doctor` prints the protocol version it proved: 15 on testnet and 14 on mainnet.
- **Document history** (for example a repository's settings history) pages by revision: on protocol 15 each page continues after the last revision read, and on protocol 14 it starts at the last revision's time and skips revisions already read.
- **Organizations (testnet only)** sign with a pure-Rust BLS library (`blstrs_plus` 0.10) in place of blst's assembly, because the new SDK needs a newer blst than the old library allowed. The signatures are the same: the organization signing test vectors pass unchanged.

Nothing else changed in the tools. Everything in [v0.3.0](v0.3.0.md) still applies.

## Upgrading from v0.3.0

Install v0.3.1 over v0.3.0 the usual way (below). Nothing needs migrating: v0.3.1 reads v0.3.0's config file, stored keys and key backups as they are, and does not rewrite them.

## Known limitations

- **The SDK is a release candidate**, 5.1.0-rc.2: when this release was built it was the newest Platform SDK on npm, and the only one there that speaks protocol 15. A later release moves to 5.1.0.
- **Settings that follow your identity and organizations are still testnet only**, as in v0.3.0.
- The limitations listed for [v0.3.0](v0.3.0.md#known-limitations) still apply.

## Install and verify

Install, verification and the IPFS build work as in [v0.2.0](v0.2.0.md#install), with `0.3.1` in place of `0.2.0`. Release binaries are built for Linux (x86_64 and arm64, plus a static x86_64 musl build), macOS (Intel and Apple silicon) and Windows (x86_64). `SHA256SUMS` lists every file, and each file has a GitHub build-provenance attestation.

What changed is in [CHANGELOG.md](../../CHANGELOG.md). How version numbers work is in [VERSIONING.md](../VERSIONING.md).
