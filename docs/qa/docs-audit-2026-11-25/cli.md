# Docs audit 2026-11-25: cli lane

Scope: `dg` and `git-remote-dash` help, the crate READMEs, and every `dg` / `git-remote-dash` / `dash://` command in the repository's Markdown.

Method:

- Ran `--help` on all 251 `dg` commands, recursively, with a master binary built from 1b547336. Also ran `git-remote-dash --version`, `--help`, `-h` and the binary with no arguments.
- Parsed that help into a command tree. A script then extracted 1,955 `dg …` invocations from code blocks and inline code in every Markdown file outside `docs/archive/`, `docs/design/`, `docs/qa/`, `CHANGELOG.md` and the v0.1 notes. It walked each invocation through the tree and flagged unknown subcommands, unknown flags and extra positional arguments. Each hit was then read by hand; most were prose ("`dg` stores it…") or `[optional]` placeholders.
- Every `DASH_FORGE_*` variable and every `dash.*` git config key named in those docs exists in code.
- Every `dash://` URL form in the docs parses with `crates/git-remote-dash/src/url.rs` (`dash://<owner>/<repo>`, `dash://<repo id>`).
- Historical docs (`docs/archive/`, `docs/design/`, v0.1 notes, CHANGELOG) have 331 invocations; 27 name commands that no longer exist (`dg config`, `dg repo export`, `dg ci watch`, …). They are records of their time and were left as they are.

## Product questions

1. **`git-remote-dash --help` reports an internal failure.** It prints E101 "git-remote-dash failed … unknown admin command … report it", and `-h` prints E203. Should both print the same usage text as the no-argument E201 ("run by git, not by hand", `git clone dash://<owner>/<repo>`)? That changes behavior, so it isn't done here.
2. **No release has the commands the guides now teach.** `install.sh` installs v0.2.0, which has no `--wallet`, `--scope core`, `dg repo pin`, fork `--storage`/`--no-copy` or `ipfs --open`, and whose `dg ipfs up` opens a browser by itself. The wallet docs say "build from source"; the IPFS, pin/fork and `--scope core` docs don't. Should those guides carry the same note, or will v0.3.0 (PR #688, still a draft) ship first?
3. **The `dg auth unlock` hint.** This lane changed it to point at `dg auth status`, because the command never existed. If an unlock command is wanted, for example to cache a passphrase, that is a product decision.
4. **The IPFS connection link always opens the mainnet web app.** On testnet, `dg ipfs up` (no `--origin`) prints a link to `https://forge.dashhq.org`, even when `--network testnet` is the default. The guide tells testnet users to paste the code or use `dg ipfs connect --origin https://testnet-forge.dashhq.org`. Should the default link follow `dg`'s network?
