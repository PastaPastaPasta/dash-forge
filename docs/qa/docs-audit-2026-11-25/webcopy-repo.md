## Product questions

1. **IPFS connect on mainnet (#727).** forge.dashhq.org tells people to run `dg ipfs up`. Without a mainnet default, the link it prints opens testnet-forge.dashhq.org (`crates/dg/src/ipfs/mod.rs:289`), and only the pasted code works. Should the mainnet site show `dg ipfs up --network mainnet`, or should `dg ipfs up` print both sites' links? Either one changes behavior, so it wasn't done here.
2. **Install sheet after v0.3.0.** The sheet now says the prebuilt binaries are testnet only and that the latest release predates mainnet and wallet sign-in. When the mainnet release (#688) ships, that line has to go in the same PR.
3. **R2/B2/AWS in the app.** #715 removed untested providers from the docs, but `bring-your-own-storage.md` still recommends R2, and the app still offers R2/B2/AWS presets (`lib/storage/profiles.ts`). It also recommends "your own R2 or S3 bucket" in the mirror wizard and Pin. Keep the presets, or limit the app to RustFS/Garage and generic S3? The storage lane owns the docs side.
4. **dg env hints in the CLI.** `dg` itself prints `dg env resave --env X`, `dg env mark-changed --env X` and `dg env history --env X` without the repository (`crates/dg/src/env.rs`, `crates/forge-core/src/env/service.rs`), and they fail with E201 when copied. Noted for the cli lane.
5. **Repo storage policy on testnet.** "Settings stay in this browser" (`repo-storage-policy.tsx:56,79`) predates identity-synced settings (#729, testnet only). Whether per-repo choices sync, and how to word it per network, belongs with the storage and identity lanes.
