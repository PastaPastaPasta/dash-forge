## Product questions

1. **E205 carries five unrelated meanings.** It means "unsupported git operation" in the catalogue (`user_error.rs:131`), yet dg also uses it for organizations on mainnet, wallet sign-in before protocol 14, bot push access on an older contract and X.509 signing keys. The docs now list them all under E205. Should these get their own code (for example a "not available on this network" code), so scripts can tell a shallow clone from a network gate? Codes can't change meaning once shipped, so this would only affect new codes.
2. **E103 for make-public "too large" in the web app.** The web app labels "this repo is too large to make public in the browser" as E103 ("not implemented yet"). It reads more like a size limit. Keep it, or use another code?
3. **Settings sync and phishing.** A wallet approval of a lookalike site's code now also hands over the forge-user key, which opens synced storage credentials (design §6, SECU-08), and wallets offer no rotation index for that key yet. Do we want an in-app warning beside "Scan only a code shown on forge.dashhq.org", or a "stop syncing / re-key" action, before forge-user reaches mainnet?
4. **forge-user on mainnet.** Registering it costs about 0.20 DASH and needs Pasta (owner-only). Until then, mainnet docs say settings stay per device. Should the mainnet docs mention that sync is coming?
5. **Organizations on mainnet.** Both web and dg gate them off mainnet. Is there a target date to write in organizations.md, or do we leave it as "not yet"?
