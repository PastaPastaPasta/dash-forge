# RC1 document vectors

Accept and refuse cases for the contracts (`forge-contracts/contracts/`: RC1, plus the RC2 items of `build.py`), one file per contract, plus RC2's replace and index vectors (below). They are generated by `forge-contracts/schema/vectors.py`, following the same `build.py` flags; don't edit them by hand. CI checks them in two places:

- `contracts.yml` runs `tools/contract-validate --vectors`, which uses rs-dpp v5.0.0-beta.1, and `forge-contracts/schema/variants.py`, which generates and judges the vectors of every RC2 flag combination.
- The Rust and TypeScript conformance runners of the client PRs check that every document a client builds is judged the same way.

## Case format

```json
{"item": "R-02", "name": "private ref with plaintext name", "type": "refUpdate",
 "expect": "refused", "why": "noPlain", "owner": 9, "doc": {…}}
```

- **`item`** is the RC1 item the case covers: an id from `RULES-PROPOSAL.md` or `OPPORTUNITIES.md` (R-xx, O-xx, INV-11, CL-7, CL-8, COMM-9), `D-5`, `state` (the transition rules), `base`, or an RC2 item of `design/v5/PLAN.md`, `RIDERS.md` or `MODERATION.md` (M1, S1–S3, C1, QW-069, QW2-010, MOD).
- **`expect`** is `ok` or `refused`. A document is judged as a create, in the order a node's structure validation runs the checks:
  - the JSON schema and `maxBytes`;
  - every `propertyConstraints` rule that reads no total, time or height;
  - `distinctFrom` (10419), for example a `starBeat` on your own repo or following yourself;
  - the `encryptedFor` ciphertext shape (10420): at least 32 bytes and a multiple of 16.
- **`why`** gives the reason for a refusal: the reason the first error gives. It is one of:
  - the JSON Schema keyword (`pattern`, `enum`, `required`, `maxItems`, `additionalProperties`, …);
  - the name of the broken rule (`noPlain`, `oidWidth`, …);
  - `maxBytes`;
  - the consensus error code (`10419`, `10420`, or `10417` for the 5,120-byte field limit).
- **`owner`** is the signer, given as a byte `n` (32 bytes of `n`) or as a base58 id. It is `0x07 × 32` when absent.
- **`doc`** writes an identifier as `{"$id": n}` (32 bytes of `n`) or `{"$id": "<base58>"}`, and a byte array as `{"$b": [fill, len]}` (`len` bytes of `fill`) or `{"$hex": "…"}`.

## Replace vectors (`<contract>.replace.json`)

These are replaces of a stored document, for the v5 `immutable` rules: checkRun's set-once fields (M1), a completed run's frozen evidence (S1), and a mirrored review comment's `diffHunk` (QW2-010). A case has the fields above plus `stored`, the stored document's properties, and `doc` is the document the replace writes. It is judged in the order a v5 node judges a replace:

1. The document properties, as for a create.
2. `immutable`. Each top-level property that differs from `stored` (changed, added or removed) is refused with `40128` when the type lists it by name, or lists it with a condition that holds. A condition reads the written document, with the stored one under `$old`.

`contract-validate` ports drive-abci's check (`document_replace_transition_action/state_v1`). The Rust and TypeScript runners read only `<contract>.json`.

## Index vectors (`<contract>.indices.json`)

These check the shape of the parsed contract, for the RC2 indexes: `review.toAuthor` (S2), `review.author` (S3), and the star's trending window (C1). A case looks like this:

```json
{"item": "C1", "name": "…", "type": "star", "index": "byWeek", "expect": "present",
 "properties": ["$createdAt", "repoId"], "has": {"outlivesDelete": true, "timeRange": true}}
```

- **`expect`** is `present` or `absent`.
- **`index`**: when it is left out, the case is about the document type itself.
- **`properties`** lists the index's properties, in order.
- **`has`** lists the index flags the index must have (`true`) or lack (`false`): `unique`, `rangeCountable`, `rankedCountable`, `outlivesDelete`, `timeRange`, and `derived`, which is true when some property is read through a reference.

A flag that is off produces the opposite cases, for example `toAuthor` absent.

## What the vectors don't judge

Some rules read a total or the block, and those are judged only on chain:

- `dense`;
- the transition's `c1`..`c6`;
- `lockGate`;
- `platformChunks`;
- `oneLive`;
- `atMost20`;
- `notFuture`.

Every `refersTo` / `where` / `findBy` reference is also judged only on chain. The live suite (`forge-contracts/scripts/rc1-live.mjs`, run against devnet bonsia) refuses each rule above at least once, and exercises the gates and stamps that guard membership, privacy and provenance: self-enrolment, revocation, the `vis` stamps both ways, consent, `asMember`, reply roots, check sources and wraps. Some references are not exercised negatively yet: `comment.reviewId`, `patch.sourceRepoId`, `repo.renamedTo`, `label` and `follow.identityId`.

`vectors.py` fails when a rule has neither a refusing vector nor an entry in its `LIVE_ONLY` list.
