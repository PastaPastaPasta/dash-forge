## Importer (forge-import)

Found in the showcase rebuild on moutai after the beta.6 reset (2026-09-28); evidence in `dash-forge-qa/evidence/showcase/REPORT.md`.

- **Merged PRs are recorded as closed when issues/PRs sync without `code` in the same run.** `Sink::merge_proof` returns `None` when the sink has no git mirror, and `importer.rs` gives it one only when `code` is among the synced classes (`cfg.classes.code.then(|| work.clone())`). A collab-only pass (`--sync issues,prs,labels`, which is how a mirror's recent-issue window is refreshed) therefore records every merged PR as a close, with the warning "no mirrored tip of its base … contains the merge commit (the base is not mirrored…)", even when the base is mirrored and contains the merge. Measured: dashpay/dash 99 PRs (develop mirrored at GitHub's tip `3ba0805c`; 12 of 12 sampled merge commits are its ancestors), dips 134, preact 65, fd 39, docs-platform 29, requests 27, jq 18, gitignore 18, ripgrep 13, fzf 10, glow 9, awesome 4, json 2, anyhow 1. The web shows them "Closed" (ripgrep: 0 of 55 PRs merged on chain). Fix: open the existing `--work-dir` mirror (fetch only the base refs it needs) whenever PRs sync, and say so in the warning when there truly is none. Repair is cheap: `state_events` already turns an old close into a merge event on a re-run, so re-running the collab pass writes one small event per affected PR, no git data.
- **Release assets past 4096 bytes are dropped silently.** `release.assets` is one 4096-byte JSON string; an entry (name, SHA-256, size, one URI) is about 255 B, so a release lists at most about 16 assets, and `model::fit_assets` drops from the end. dashpay/dash: 107 of 137 releases lost 621 assets (1 to 19 each); v23.1.8 keeps 16 of 21 and drops the x86_64 Linux tarball, the source tarball, their `.asc` signatures and `SHA256SUMS.asc`. The release page (`releases-content.tsx`) renders only what is stored and never says assets are missing. Two steps:
  - now: the importer records the dropped count (for example in the notes' footer or a small `assetsOmitted` field on a future schema) and the page shows "N assets not mirrored" linking to the source release;
  - design: move the list out of the 4096-byte field, either a follow-up `releaseAssets` document per 16 entries (fits the current contract model, one more write per 16 assets) or an asset manifest in the repo's storage referenced by its SHA-256 from the release (no size limit, one hash in the document; readers verify it like any stored object). The manifest keeps the release document small and makes signatures and checksum files first-class.
- **Asset hashing budget.** One run hashes at most 4 GiB of release assets; the rest are recorded without a SHA-256 and the web refuses to offer them until a later run hashes them (dashpay/dash: 1,494 assets in 98 releases). A later collab or releases run fills them in; say so in the import summary with the count, and consider hashing newest releases first.
- **D-920 also hit a 3 MB repository.** serde-rs/json imported with master's build before #135 showed "Not indexed for browsing" (no warning from that build); `dg repo reindex` from the fix build repaired it for 0.116 DASH. The fix build reports `indexSkipped`, so imports after #135 are covered; mirrors imported before it should be checked once.

## Web: code browsing

- **Port xdiff's diff for exact blame parity.** Web blame (`forge-web/lib/view/blame.ts`) aligns lines with our Myers diff plus a port of git's change compaction and indent heuristic (`xdiff-compact.ts`). On about 1–2% of random edit histories it still gives a line to a different commit than `git blame --first-parent`: where a line repeats and moves, xdiff's own diff (`xdl_do_diff` with `xdl_cleanup_records`) pairs different copies. The case is recorded in `blame.test.ts`, under "known differences". The UI says blame is computed in the browser and can differ from `git blame`. For exact parity, port `xdl_do_diff` and `xdl_cleanup_records`, then turn the known-difference test into an equality test.
- **Blame through renames with edits.** Only exact renames are followed (the same blob, deleted elsewhere by the commit that added the path). Git scores similarity. The UI notes the case when the add commit also deleted a file of the same name.
